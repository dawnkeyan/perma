## 1. 背景与问题

### 1.1 用户侧问题

现代人的情绪困扰呈现三个特征：

1. **记录断裂** —— 情绪是流动的，但多数人只在崩溃时回想，日常只有模糊感受，无法回看模式。
2. **干预门槛高** —— 心理咨询单价高、时间成本大，从"想调整"到"预约"之间存在巨大流失。
3. **认知偏差放大** —— 人在低落时倾向于自动化归因（"我真没用"），缺少一个能温和指出的第三方视角。

### 1.2 产品定位

> **Lumina 是一个基于积极心理学的 AI 情绪教练。**
> 它不是诊断工具，不是替代治疗，而是"随时在场的、结构化的、科学的自我觉察陪练"。

定位三原则：

| 原则 | 含义 | 反面例子 |
| --- | --- | --- |
| **不诊断** | 只做心理普适性引导，不做 DSM 诊断、不给疾病结论 | "你可能是抑郁症" |
| **不替代** | 明确告知 AI 能力边界，引导专业求助 | 无限次"我懂你" |
| **有行动** | 每次对话结束必须落到一个 5 分钟内可完成的微行动 | 只输出共情文案 |

### 1.3 竞品与差异化

| 产品 | 优势 | 局限 | Lumina 的差异 |
| --- | --- | --- | --- |
| 通用 AI 助手 | 能力强、免费 | 无结构、无记忆、无方法论、给建议流于鸡汤 | 强制走结构化干预流程，且每次输出都可溯源到心理学依据 |
| 传统日记 App | 记录方便 | 记录完就结束，无反馈无洞察 | 记录即输入，AI 主动生成洞察与微行动 |
| 心理健康 App | 方法论专业 | 付费墙高、内容静态、无个性化 | 知识库 + RAG 把专业内容个性化到个人上下文 |

## 2. 目标用户

### 2.1 画像

**主用户 Persona：阿May，27 岁，互联网产品经理**

- 画像：工作节奏快、长期高压、社交耗竭、有自我成长意愿但没时间系统学习心理学。
- 痛点：晚上刷手机两小时，第二天上班像没充满电；知道要"情绪管理"但不知道怎么做。
- 目标：3 分钟内完成记录，获得一个当下就能做的小动作。
- 付费意愿：中低，但为"AI 教练不限次数 + 深度周报"愿意单次付费 12 元。

**次用户 Persona：小陈，34 岁，程序员**

- 画像：理性、内向、对心理学概念抵触但接受"数据化自我观察"。
- 痛点：情绪波动但不愿意"写日记"，抵触鸡汤。
- 目标：把情绪当指标看——趋势、触发因子、恢复时长。
- 付费意愿：高，为长期趋势报告与数据导出付费。

### 2.2 规模假设（MVP 阶段）

- 内测 300 人
- 7 日留存目标 ≥ 25%，30 日留存目标 ≥ 12%
- 日活目标 60，日均对话轮次 4.2

## 3. 核心用户旅程

```
打开小程序
   │
   ├─→ 今日打卡（30 秒）  ──→ 情绪标签 + 强度 + 一句话
   │        │
   │        └─→ 触发 AI 主动关心（可选推送）
   │
   ├─→ 和 AI 教练对话（3~5 轮）
   │        │
   │        ├─ 系统：检索心理学知识库（RAG）
   │        ├─ 系统：读取近 7 天情绪历史作为上下文
   │        ├─ 系统：安全检测（危机识别 / 医疗越界识别）
   │        └─ 输出：共情 → 洞察 → 认知重构 → 微行动
   │
   ├─→ 选一个工具（如「心绪导航」）
   │        │
   │        ├─ 展开查看这一步会做什么（不黑箱）
   │        ├─ 系统：按工具的检索侧重 + 情绪上下文执行
   │        └─ 输出：识别状态 → 匹配干预策略 → 每条建议带引用来源
   │
   ├─→ 认知重构练习（2 分钟）
   │        写下自动想法 → AI 找证据偏差 → 生成替代性想法
   │
   └─→ 成长时间线（回顾）
            情绪趋势 + 触发因子 + 优势记录 + 连续打卡天数
```

## 4. 功能需求

### 4.1 情绪打卡（P0）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F-1.1 | 8 种情绪 emoji 快选（喜悦/平静/期待/感动/疲惫/焦虑/低落/愤怒） | P0 | 单次点击完成，≤ 5 秒 |
| F-1.2 | 情绪强度 1~5 星滑动选择 | P0 | 默认 3 星，滑动手势流畅无掉帧 |
| F-1.3 | 自由文本"发生了什么"（≤ 500 字） | P0 | 支持输入法联想，无乱码 |
| F-1.4 | 情绪标签多选（工作/人际/身体/财务/自我/未来） | P0 | 最多 3 个 |
| F-1.5 | 打卡时间轴展示 | P0 | 按日聚合，显示当次记录详情 |
| F-1.6 | 连续打卡天数 + 徽章 | P1 | 连续 3/7/21/100 天徽章 |

**数据规则**：同一天允许多条记录（用户情绪日内会变），时间线展示当日平均强度。

### 4.2 AI 教练对话（P0，核心）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F-2.1 | 文本对话，流式输出 | P0 | 首字响应 < 1.5s，Token 间隔 < 300ms |
| F-2.2 | 回答附「依据来源」，可展开查看引用的知识库条目 | P0 | 引用条目 ≥ 1 条且可跳转原文 |
| F-2.3 | 每次回复末尾给出「一个微行动」 | P0 | 必须是 5 分钟内可完成的单条动作 |
| F-2.4 | 自动带入近 7 天情绪记录作为上下文 | P0 | 询问"我最近怎么样"能正确回答 |
| F-2.5 | 点赞 / 点踩 + 一键填写点踩原因 | P0 | 点踩原因必填（至少 4 个选项 + 自由文本） |
| F-2.6 | 话题小结（conversation summary） | P1 | 每 20 轮生成，存入用户记忆 |
| F-2.7 | 语音输入 | P2 | 微信同声传译 API |

**对话输出结构协议（内部约定，模型须遵循）**：

```
[共情] 1~2 句，复述用户感受，确认情绪被理解
[洞察] 1 句，指出用户陈述中的模式/触发因子/认知偏差
[依据] 2~4 条心理学方法或知识库条目，带引用角标
[微行动] 1 条，5 分钟内可完成，祈使句
```

### 4.2.1 工具入口（P0）

「工具」是比「页面」更产品化的一层抽象：一个工具 = 一段被产品定义好的引导流程
+ 一组检索侧重 + 一句固定话术，**不新增执行链路**，只是对现有教练链路的一次参数化预设。

| 编号 | 工具 | 简介 | 流程 | 优先级 |
| --- | --- | --- | --- | --- |
| F-2.8 | 心绪导航 | 情绪低落时，先识别状态，再匹配干预策略。每条建议都可追溯来源。 | ① 识别当前状态 → ② 匹配干预策略 → ③ 查看建议来源 | P0 |

**产品规则**：

- 工具卡片文案由服务端目录下发（`GET /v1/tools`），产品改一句话不需要发版
- 用户进入前可展开查看完整流程步骤（「AI 不做黑箱」原则）
- 工具入口**不绕过**安全链路：用户在工具里表达危机，仍走硬编码干预话术
- 「每条建议都可追溯来源」由引用链路保证：检索命中 → 引用角标 → 可展开原文与证据等级
- 检索侧重（focus）不下发客户端，避免客户端与检索实现耦合

**验收标准**：

| 编号 | 验收项 | 标准 |
| --- | --- | --- |
| A-2.8.1 | 首页工具卡片 | 展示名称 + 简介 + 可展开的三步流程 |
| A-2.8.2 | 工具生效 | 从工具进入的请求携带 `tool_id`，服务端按该工具的检索侧重与上下文要求执行 |
| A-2.8.3 | 来源可追溯 | 工具内输出的每条建议都带引用角标，引用有效率 ≥ 0.93 |

### 4.3 认知重构练习（P1）

基于 CBT 的 `认知重构`（Cognitive Restructuring）：

1. 用户写下"情境 / 自动想法 / 情绪强度"
2. AI 识别可能的认知偏差（灾难化、以偏概全、非黑即白等）
3. 引导用户自己找证据（而不是 AI 直接给答案）
4. 生成"替代性想法"并对比情绪强度变化

> 设计要点：第 3 步刻意做成**引导式提问**而非代劳，这是循证 CBT 的核心机制，也是本产品与"AI 帮你想开点"的根本区别。

### 4.4 优势与价值观测评（P1）

- 基于 VIA 24 项优势（六大类：智慧与认知、勇气、人际、仁慈、正义、生命力）
- 30 题自适应问卷（IRT 简化实现：每题 5 级李克特，题目按区分度动态选取）
- 输出 Top 5 优势 + 优势盲点提示 + 基于优势推荐的微行动
- 参考：Seligman & Csikszentmihalyi (2000)

### 4.5 成长时间线（P1）

- 情绪趋势折线（近 7/30/90 天）
- 触发因子 Top N 统计（基于标签 + 对话中识别的因子）
- "高强度负面情绪"自动聚类 → 发现模式
- 周报卡片：本周情绪基调、最常触发的场景、恢复时长中位数、1 条建议
- 数据导出（CSV / JSON）

### 4.6 通知与主动关心（P2）

- 每天固定时段（用户可配）推送打卡提醒
- 连续 2 天未打卡且历史显示状态下滑 → AI 生成一条个性化关心消息
- 打卡后情绪强度 ≤ 2 且连续 3 天 → 主动推送正反馈

### 4.7 安全与合规（P0，最高优先级）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F-7.1 | 危机词检测（自伤/自杀/轻生） | 命中后立即停止常规生成，输出固定危机干预话术 + 全国心理援助热线 + 「立即拨打 120」引导 |
| F-7.2 | 医疗越界检测 | 用户问"我是不是抑郁症"→ 明确声明非诊断，建议就医，不给结论 |
| F-7.3 | 无响应兜底 | 危机场景下**不允许**返回任何兜底闲聊话术 |
| F-7.4 | 用户数据可导出、可彻底删除 | 删除后 30 天内从主库与备份清除 |
| F-7.5 | 隐私政策与用户协议 | 上线前法务确认；明示"数据用于服务改进，可选择退出" |

> **危机干预话术必须硬编码在应用层，不经过 LLM 生成**，避免模型幻觉出错误资源信息。

### 4.8 运营与内测后台（P1，支撑"真实环境"）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F-8.1 | BadCase 看板 | 点踩 / 低分回答 / 人工标注，自动进入待处理队列 |
| F-8.2 | 标签体系 | 至少 8 个归因标签：检索召回错误、上下文丢失、指令遵循差、幻觉、过度共情、越界医疗、格式错误、延迟过高 |
| F-8.3 | Prompt 版本管理 | 每次上线可回滚；对比任意两版在同一评测集上的指标 |
| F-8.4 | 灰度与开关 | 按用户 ID 哈希分桶，可对特定功能做 1%/10%/50% 灰度 |
| F-8.5 | 埋点看板 | 漏斗、留存、对话轮次、Token 成本、p95 延迟 |

## 6. 关键指标

**北极星指标：周活跃用户中的「有效干预次数」**

> 有效干预 = 用户完成了至少一次微行动打卡（含打卡、认知重构、优势练习任一）。

| 层级 | 指标 |
| --- | --- |
| 获取 | 小程序访问 UV、新增注册 |
| 激活 | 完成首次打卡率（目标 60%）、首次对话率（目标 45%） |
| 留存 | 次日 / 7 日 / 30 日留存 |
| 参与 | 人均周打卡次数、人均周对话轮次、微行动完成率 |
| 质量 | 点踩率（目标 < 6%）、有引用率、危机识别召回率 |
| 成本 | 单有效干预成本、单用户日均成本 |
| 稳定性 | 错误率、超时率、降级触发率 |

## 10. 附录：心理学方法论依据

| 功能 | 理论 | 出处 |
| --- | --- | --- |
| 情绪记录与模式识别 | 情绪粒度（Emotion Granularity） | Barrett, 1997 / 2017 |
| 认知重构 | 认知行为疗法 · 记录式思维记录 | Beck, 1976 |
| 优势测评 | VIA 优势分类 | Seligman & Csikszentmihalyi, 2000 |
| 微行动 | 行为激活（Behavioral Activation） | Jacobson, 2001 |
| 感恩干预 | 感恩练习 | Seligman et al., 2005 |
| 积极重评 | 积极重述 / 积极重评干预 | Cacciatore et al., 2007 |
| 心流与投入 | 心流理论 | Csikszentmihalyi, 1990 |
| 复原力 | 复原力理论 | Masten, 2001 |

> 上述条目同时是 RAG 知识库的元数据标签体系来源。
