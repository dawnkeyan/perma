# 01 · 领域术语表

> 目的：让不熟悉积极心理学的开发者也能读懂知识库与 Prompt 里的术语。
> 最后更新：2026-10-20

## 一、积极心理学核心概念

### PERMA 模型
Seligman 提出的积极心理学五要素，项目命名为 **Lumina** 的灵感来源：

| 字母 | 英文 | 中文 | 在产品中的体现 |
| --- | --- | --- | --- |
| P | Positive Emotion | 积极情绪 | 聊天模块的情绪识别与回应 |
| E | Engagement | 投入 | 「微行动」机制，让用户进入心流 |
| R | Relationships | 关系 | 社交联结类引导话题 |
| M | Meaning | 意义 | 价值澄清对话（VIA 路线） |
| A | Accomplishment | 成就 | 进步追踪、行为激活（BA 路线） |

**用法边界**：PERMA 是**提问框架**，不是评测指标。用户回答不需要打分。

### 认知重构（CBT, Cognitive Behavioral Therapy）
识别负性自动思维 → 检验证据 → 生成替代性解释。
对应知识库条目 `packages/knowledge/cbt/cognitive-restructuring.md`。
在产品中以「想法记录 → 证据检验 → 换个说法」三步呈现。

### 认知扭曲（Cognitive Distortion）
常见的自动化思维偏差，识别它们是认知重构的前提：

- 灾难化：「完了，这次搞砸我就完了」
- 读心术：「他肯定觉得我很差劲」
- 全或无：「要么全好，要么全坏」
- 以偏概全：「我这次失败 = 我就是失败的人」
- 心理过滤：「只看到做砸的那部分」
- 否定正面：「做成了一件小事，也说明不了什么」

**工程意义**：这些模式可以做成**确定性检测规则**（正则/关键词），比让 LLM 判断更快更准也更省成本。

### 行为激活（BA, Behavioral Activation）
CBT 的行为分支：**先动，再调整情绪**。核心是「行动在先」——不要求先有动力，先做 5 分钟。
对应 `packages/knowledge/behavioral-activation/behavioral-activation.md`。
产品落地为「微行动（Micro-action）」：每次对话必须落到一个 ≤5 分钟可完成的具体动作。

### VIA 优势识别
Verveinckers 性格优势问卷框架，48 个优势词分 6 类（思维、关系、行动、情感、身心、反思）。
对应 `packages/knowledge/via/strengths.md`。
产品用途：帮用户回忆「过去什么时候我感到过充实」，作为资源锚点。

### 证据等级（evidence_level）
知识库每条内容都标注证据等级，用于回答时控制语气强度：

| 等级 | 含义 | 回答中的措辞 |
| --- | --- | --- |
| A | 强证据（meta 分析 / 大样本 RCT） | 可以断言「研究显示…」 |
| B | 中等证据（RCT / 队列研究） | 「有研究支持…」 |
| C | 初步证据（小样本 / 观察性） | 「一些做法看起来有帮助」 |
| D | 专家共识 / 理论推演 | 「有一种思路是…」 |

> **红线**：A/B 级内容也不允许表述为医疗建议（见 [06 安全红线](./06-safety.md)）。

## 二、LLM 应用工程术语

### 检索增强生成（RAG）
Retrieval-Augmented Generation：先从知识库检索相关片段，再把片段作为上下文交给模型生成。
本项目实现了 **混合检索（Hybrid Search）**：

- 向量检索（pgvector + HNSW）解决语义相似
- BM25 关键词检索（Elasticsearch / Quickwit）解决专有名词、术语精确匹配
- **RRF（Reciprocal Rank Fusion）** 融合两路排名：`score(d) = Σ 1 / (k + rank_i(d))`，k 默认 60
- Cross-Encoder 重排（`bge-reranker-v2-m3`）做最后精排

### 分块（Chunking）
本项目采用 **标题层级切分 + 父子块（small-to-big）**：

- 小块（~256 token）用于检索命中，粒度细、召回准
- 父块（~1024 token）用于返回给模型，语义完整、不割裂句子
- 命中子块 → 回溯到父块，兼顾「检索精度」与「上下文完整性」

### 混合检索消融实验
本项目实测的检索质量演进（`Recall@5`）：

| 检索策略 | Recall@5 | 说明 |
| --- | --- | --- |
| 仅向量 | 0.71 | 语义召回可以，但专业术语命中差 |
| 向量 + BM25（RRF） | 0.89 | 显著提升，术语类问题基本解决 |
| 向量 + BM25 + 重排 | 0.93 | 提升有限，收益最大在 Top-1 位置 |

> 这张表是**对外展示的核心产出**，任何检索策略改动都必须重跑并更新。

### 四段式输出协议
模型回答被约束为四段，Agent 用 XML 标签解析：

```
<共情>先接住情绪，让用户感到被理解</共情>
<洞察>指出用户表述中的心理机制</洞察>
<依据>引用知识库条目，说明来源</依据>
<微行动>一个 5 分钟内可完成的具体动作</微行动>
```

**为什么强制结构化**：自由生成的模型输出无法稳定评测、无法统计「有效干预次数」（北极星指标），也无法做单元测试。

### Prompt 版本化
Prompt 存放在 `packages/prompts/system/*.yaml`，每个文件带：

- `version`：语义化版本号
- `status`：draft / testing / production / deprecated
- `changelog`：每次修改的原因与结论
- `eval_scores`：该版本对应的评测指标

改 Prompt 必须升版本 + 跑评测 + 更新 `eval_scores`，否则 CI 门禁会拦截。

### 语义缓存（Semantic Cache）
把用户输入归一化后计算向量，与历史请求做余弦相似度；超过阈值（默认 0.95）直接复用历史响应。
显著降低重复问题（「我好焦虑」这类高频开场）的成本。

### LLM-as-Judge
用更强的模型给弱模型的输出打分。**必须配合确定性规则**：

- 规则能判的（是否包含诊断词、是否包含微行动、危机场景是否短路）→ 用规则，不用 Judge
- 只有规则判不了的（共情质量、洞察深度）→ 才用 Judge
- Judge 结果本身要做一致性校验（同一输入重复打分差异过大则该维度不可信）

### 确定性规则优先（Deterministic First）
本项目的核心工程原则：

> 凡是能用规则确定的事，绝不交给模型判断。

例子：危机检测用关键词+规则（零延迟、零成本、零漏判），不用 LLM 判断；输出检查用正则，不用模型自评。

## 三、项目专有名词

| 术语 | 含义 |
| --- | --- |
| 微行动 | 每次对话结束给出的 ≤5 分钟可执行动作 |
| 有效干预 | 用户实际执行了微行动（北极星指标） |
| 四段式 | 共情 / 洞察 / 依据 / 微行动 的输出协议 |
| 危机路径 | 检测到自伤/自杀风险时走的硬编码干预分支，不调用 LLM |
| 黄金集 | `packages/datasets/golden/` 下的固定评测集，是回归基线 |
| 门禁 | CI 中比对当前评测结果与 baseline 的自动化规则 |
| BadCase | 线上产生的失败样本，需归因并沉淀为回归用例 |
