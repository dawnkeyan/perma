# 安全与隐私规则

> **本文件的优先级高于任何功能需求。** 功能需求与本文件冲突时，以本文件为准，
> 并在 PR 描述里说明这个冲突。

## 一、三条不可协商的红线

### 红线 1：危机场景绝不调用模型

**规则**：命中危机信号时，请求必须在 LangGraph 的 `entry` 节点**直接短路**，
返回 `crisis_response()` 的硬编码话术。**不得**调用任何模型。

**为什么**：这条路径的**确定性**就是它存在的理由。
如果它依赖模型，那么模型超时、限流、故障、幻觉都会让它失效——
而这恰恰是用户最需要它工作的时刻。

**守护测试**：`services/api/tests/test_safety.py::test_crisis_response_never_uses_model`

**禁止的改法**：
- ❌ 用模型生成危机回应
- ❌ 用 LLM 提高危机识别率（要提召回请扩规则词表）
- ❌ 在危机路径上加「重试」

### 红线 2：不做医疗诊断

- 输入侧：`detect_medical_overreach()` 识别索要诊断/用药的意图
- 输出侧：`check_output_for_diagnosis()` 拦截诊断式结论
- 「建议你去医院 / 找专业心理咨询师」是**正确**引导，有专门放行规则（`_ALLOWED_REFERRAL`），不要误伤

### 红线 3：不做虚假承诺

不允许「一定会好」「保证你」「没事的」「会过去的」。

## 二、隐私

用户数据是**情绪记录**，属于高度敏感信息。

| 环节 | 硬性要求 |
| --- | --- |
| 应用日志 | **不得出现**用户原文、完整模型输入输出 |
| 链路追踪 | **不得出现** `llm.prompt` / `llm.completion` / `user.message` / `db.statement` |
| 数据库 | 查询日志不得打印用户内容；ORM `__repr__` 不输出用户原文（**不要改回去**） |
| 模型调用 | 只传必要上下文；`llm_calls` 只记元数据（token、成本、耗时），不记完整 prompt |
| 埋点 | 只上报事件类型与数值，**不带内容** |
| 测试数据 | 用 `packages/datasets/golden/` 的**合成用例**，不要粘贴真实用户内容 |
| Issue / PR | 贴日志前脱敏：去掉 openid、token、手机号、用户原文 |

## 三、密钥

| 变量 | 敏感度 | 泄漏后果 |
| --- | --- | --- |
| `LLM_API_KEY` | 高 | 直接产生费用 |
| `JWT_SECRET` | 高 | 可伪造任意用户 token |
| `POSTGRES_PASSWORD` / `REDIS_PASSWORD` | 高 | 数据全量泄漏 |
| `MODELSCOPE_TOKEN` | 中 | 可读写模型仓库 |
| `GRAFANA_PASSWORD` | 中 | 监控数据泄漏、横向移动风险 |

**规矩**：
- `.env` 不进 Git；`.env.example` 只放占位符
- 生产密钥由环境注入，不写在代码或 compose 文件里
- 不把密钥写进日志（包括「临时打印看看」）
- 提交前本地跑 `gitleaks detect --source . --redact`

## 四、AI 助手额外要求

当被要求修改涉及以下范围的代码时，**必须先读**
`services/api/app/agents/safety.py` 与 `services/api/tests/test_safety.py`：

- 安全检测逻辑（危机 / 医疗 / 注入）
- Prompt 中的禁止条款
- 图的路由与短路分支
- 输出后校验
- 日志与追踪的字段处理

并且：

1. **先补测试再改实现**（测试先失败，再让它通过）
2. 改动后必须跑 `pytest services/api/tests/test_safety.py` 并在 PR 里贴结果
3. 如果改动**削弱**了任何一条红线的覆盖，**拒绝执行**并说明原因
4. 不要在代码注释、文档、提交信息里写「只是暂时去掉检查」这类临时绕过——
   临时绕过必须有 issue 编号和删除期限

## 五、紧急情况

| 情况 | 立即动作 |
| --- | --- |
| 密钥泄漏 | 轮换密钥 → 查 `llm_calls` 确认是否被使用 → 查 Git 历史 → 必要时清历史 |
| 危机路径误调模型 | **视为 P0**，立即回滚到上一个版本，恢复纯规则路径 |
| 日志出现用户原文 | 立即清理日志存储 → 缩小脱敏规则 → 检查所有 logger 调用点 |
| 发现诊断式输出 | 视为 P0，加进 `check_output_for_diagnosis` 的正则 → 补回归用例 |
